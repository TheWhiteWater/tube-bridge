# ADR-004 — v1.1.0 Release Test Contract Supersession

**Status:** Accepted for the operator-authorized v1.1.0 release candidate
**Date:** 2026-08-10
**Scope:** Test-hash authority and release verification only

## Context

The v1.0.3 frozen manifests correctly describe the historical 16-tool release. v1.1.0 intentionally changes the public contract to 17 tools, adds MCP `ImageContent`, changes default subtitle selection, adds an Agent Plugin preview, and strengthens the Docker/release boundary. Several v1.0.3 tests encode exact 16-tool counts or broad `COPY . .` assumptions and therefore cannot remain the hash authority for the new release line.

Leaving those historical hashes as if they governed v1.1.0 creates two bad outcomes: either the new product contract cannot be tested, or tests are changed without an explicit supersession record. Neither is acceptable.

## Decision

1. Preserve every prior frozen manifest and its referenced commits as immutable historical evidence for the release it governed.
2. Supersede current hash authority of:
   - `.brainops/methodology/frozen-tests/frozen-tdd-wi-00028-core-publication-001-python.json`;
   - `.brainops/methodology/frozen-tests/frozen-20260809073048-tests.json`.
3. Establish `.brainops/methodology/frozen-tests/frozen-v1.1.0-release-candidate-tests.json` as the authoritative v1.1.0 candidate manifest for the complete deterministic `tests/` Python suite.
4. Record the linkage in `.brainops/methodology/frozen-tests/supersession-v1.1.0-release-contract.json`.
5. Preserve the ADR-003 retirement manifest as historical evidence while superseding current hash authority for its transcript-error test: v1.1.0 must preserve the original listing/network failure and must not probe an implicit English track after language-cohort discovery fails. This does not weaken self-hosted-only, private-endpoint, credential, or no-Railway requirements.
6. Add new behavior through separate tests, including `test_transcript_track_selection_addendum.py`, rather than rewriting the already-frozen subtitle selector file.
7. Do not tag or publish v1.1.0 until the authoritative manifest matches the working tree, the complete deterministic suite passes, and an independent final audit reports P0=0/P1=0.

## Release Boundary

This supersession authorizes no hosted service and no Railway deployment. GitHub/PyPI/GHCR remain the only runtime publication surfaces; the Agent Plugin preview is a separate GitHub Release asset with manual dependency bootstrap.

## Consequences

- Historical v1.0.3 acceptance remains reproducible from its tag and manifests.
- v1.1.0 tests may state the new 17-tool and explicit-Docker-allowlist contracts honestly.
- Any subsequent change to a file listed in the v1.1.0 manifest requires another explicit addendum or supersession.
- Post-publication live receipts are appended after registry verification; they do not retroactively alter the candidate test hashes.
