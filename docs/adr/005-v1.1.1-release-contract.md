# ADR-005 — v1.1.1 Patch Release Contract

**Status:** Accepted
**Date:** 2026-08-10
**Authority:** Operator
**WorkItem:** WI-RELEASE-1.1.1-20260811

## Context

The Corpus v1 ranking and result-metadata hardening was implemented, frozen, audited, merged, and verified independently after immutable v1.1.0 publication. The Operator has now authorized publication if the release candidate passes its complete gates.

Three historical tests contain exact current-development-version assertions that correctly named v1.1.0 at the time, but cannot remain the current-version authority for v1.1.1.

## Decision

1. Publish the already-merged Corpus v1 hardening as patch release `v1.1.1` only after the complete deterministic, package, plugin, container-boundary, live-ranking, documentation, hosted-CI and conformance gates pass.
2. Supersedes the current-version assertions in `tests/test_v1_0_3_release_contract.py`, `tests/test_agent_plugin_contract.py`, and `tests/test_frame_tool_contract.py`; their behavioral, privacy, plugin and historical-release assertions remain active.
3. Establish `tests/test_v1_1_1_release_contract.py` and its Station-generated frozen manifest as the patch-release authority.
4. Historical v1.1.0 artifacts remain immutable. Their checksums and publication receipt are preserved and are not rewritten or yanked.
5. Public distribution remains limited to GitHub Release, PyPI and GHCR. The private Railway service is not deployed, modified, or advertised.
6. Corpus v2 remains a frozen contract only. This release does not implement `CorpusV2Store` or cut over the five corpus tools.
7. The Agent Plugin remains a preview with operator-managed dependency bootstrap.

## Acceptance

- Exact `1.1.1` identity across package, MCP server/help and plugin.
- Frozen ranking and addendum tests retain their audited hashes and execute in the complete suite.
- Existing v1 databases migrate additively and legacy vector tables split transactionally when needed.
- A fresh four-video live run has no strict same-video temporal overlap, represents all four sources within the candidate pool, and returns titles plus canonical timestamp URLs.
- Wheel, sdist, clean install, plugin ZIP and Docker runtime boundaries pass without credentials or private deployment metadata.
- Independent audit and Station conformance report `PASS`, with P0=0 and P1=0.
- Tag-triggered publication and downloaded-artifact verification pass before the WorkItem closes.
