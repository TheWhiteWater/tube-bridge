# tube-bridge v1.1.1

A self-hosted patch release for more useful and deterministic Corpus v1 search results.

## Corpus v1 ranking

The release:

- suppresses strict same-video temporal overlap among returned chunks;
- applies deterministic source-aware per-video caps with refill when alternate sources enter the candidate pool;
- returns cached titles and canonical YouTube timestamp URLs;
- validates `top_k` in the public 1–50 range and uses bounded candidate over-fetch;
- makes vector-table names collision-resistant and transactionally splits legacy colliding tables;
- removes only the target video's vectors during `force_reembed`.

These controls improve result diversity and provenance usability. Similarity scores remain ranking signals, not confidence or evidence-quality claims. A source cap cannot surface a source that did not enter the semantic candidate pool.

## Compatibility

Existing v1 `corpus.db` files migrate additively. Cached titles are nullable and best effort. Legacy shared vector tables are split transactionally without changing corpus IDs, tool names, embedding model, or the fixed 80-second/20-second-overlap chunking policy.

Corpus v2 is not implemented by this release. The frozen Corpus v2 contract remains future design material; all five corpus tools continue to use the v1 runtime.

## Product boundary

Public distribution is limited to GitHub Release, PyPI, and GHCR. The private Railway service was not deployed or modified for this release. No hosted demo, OAuth service, managed corpus storage, account system, shared quota, or SLA is introduced.

Historical v1.1.0 artifacts remain immutable and unyanked. The Agent Plugin remains a preview with one discoverable skill and manual dependency bootstrap.
