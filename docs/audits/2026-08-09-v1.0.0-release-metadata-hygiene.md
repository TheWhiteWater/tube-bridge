# v1.0.0 Release Metadata Hygiene Audit

**Date:** 2026-08-09  
**WorkItem:** WI-00034  
**Status:** Accepted  
**Scope:** PyPI and GitHub release metadata only; no package, demo, tag, asset, credential, or runtime changes.

## Finding

The `v1.0.0` wheel and sdist are functional historical artifacts, but their embedded README/PyPI long description contains stale publication-state wording. It says that the core was not externally published and that hosted CI still required an authorized push even though `v1.0.0` was itself published to PyPI and GitHub.

This was a documentation-metadata defect, not a package-functionality, compatibility, or security defect.

| Release | Audit result | Disposition |
|---|---|---|
| `1.0.0` | Functional artifacts; stale embedded publication-state text | Preserve on PyPI without yank; mark GitHub release superseded for metadata by `v1.0.2` |
| `1.0.1` | Corrected publication metadata | Preserve unchanged |
| `1.0.2` | Current release | Preserve unchanged |

## Disposition Decision

The Operator directed completion of the release audit and hygiene in Station session `S-01024`. The bounded independent pre-action audit concluded that retaining PyPI `1.0.0` unyanked and adding an explicit GitHub supersession notice is appropriate and sufficient.

PyPI's official yanking guidance says yanking should be used sparingly because it can disrupt downstream users, and identifies broken/uninstallable releases, compatibility violations, and security vulnerabilities as the normal reasons to yank. None applies here. A documentation-only historical defect does not justify making a functional version invisible to normal resolver selection.

Therefore:

1. PyPI `1.0.0` remains unyanked.
2. GitHub release `v1.0.0` is titled **“v1.0.0 — superseded by v1.0.2”**.
3. Its release body explains that only the embedded publication-state wording is stale, recommends `v1.0.2` for new installs, and explicitly says this is not a security or functionality withdrawal.
4. The `v1.0.0` tag and both release assets remain unchanged.
5. Releases `v1.0.1` and `v1.0.2` remain unchanged.
6. No PyPI token, recovery code, GitHub secret, package source, demo behavior, or published artifact was modified.
